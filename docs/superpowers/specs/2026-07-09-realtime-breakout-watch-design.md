# 실시간 돌파 감시 봇 — "넓은 감시 모드" 설계

작성: 2026-07-09

## 1. 배경 & 목표

지금 자동매수 봇(`scripts/autobuy/runner.py`)은 **아침에 뽑힌 "진입임박(actionable+entry_ready)" 종목만** 감시한다. 그래서 전날 "예의주시(forming)"였다가 **장중에 거래량 터지며 피벗을 뚫는 종목**(예: S-Oil우 7/7 — 7/6엔 forming, 7/7 거래량 2.89배로 돌파)을 아예 보지 못하고 놓친다.

봇은 이미 실시간 폴링 + 판정(피벗 돌파 · 거래량 페이스 · 추격 +3% 이내 · 슬롯)을 **다 하고 있다.** 부족한 건 단 하나 — **감시 목록이 너무 좁다는 것.**

**목표:** 감시 목록을 진입임박 + **예의주시**까지 넓혀, 그중 누가 장중에 "피벗+3% 이내에서 거래량 터지며 돌파"하면 그 순간 잡는다. (예측이 아니라 실시간 반응.)

## 2. 접근 — A안 (기존 로직 재사용, 감시 목록만 확장)

새로 만드는 것은 **넓은 감시 목록 로더 하나**뿐. 실시간 포착 로직은 기존 것을 그대로 쓴다.

- 기존 라이브 봇(`runner.py`)의 기본 동작은 **건드리지 않는다.** 넓은 감시는 **옵션(`--broad`)으로만** 켜진다(옵트인).

## 3. 감시 목록 정의 — `load_watchlist_broad`

`scripts/autobuy/watchlist.py`에 새 함수 추가. 기존 `load_actionable`과 나란히 둔다(대체 아님).

- **입력**: `config.CANDIDATE_PATHS` — 현재 `sepa-vcp / sepa-3c / sepa-power-play` 세 파일(트렌드템플릿 통과분).
- **포함 조건**: `status ∈ {actionable, forming}` **AND** `pivot_price` 존재.
- **제외**:
  - `status = breakout` (이미 피벗 위 = 대개 익스텐디드, 추격됨)
  - `status = failed`
  - `pivot_price` 없는 것(감시할 기준선이 없음)
  - **파워플레이 "전체종목(RS80↑)" 파일(`sepa-power-play-all-candidates.json`)** — 트렌드템플릿 미필터라 제외. (현재 `CANDIDATE_PATHS`에 애초에 없으므로 자동 제외되나, 향후 추가 방지 위해 명시.)
- **중복 처리**: 같은 종목이 여러 패턴에 있으면 1건으로 합침. **패턴 우선순위 `VCP > 3C > 파워플레이`** 순으로 택 1(그 패턴의 피벗 사용). 만약 그 피벗이 이미 +3% 초과여도 `evaluate_entry`의 추격 게이트가 자동으로 거르므로 안전.
- **출력**: `[{code, name, pivot, pattern}, ...]` (기존 `load_actionable` 반환 형태와 동일 → 다운스트림 무변경).

## 4. 안전한 2단계 진행 (phasing)

**1단계 — 관찰기 먼저 (읽기 전용, 주문 없음).**
`verify_volume.py`에 `--broad` 옵션 추가 → 넓은 목록으로 **실제 거래일 장중에 돌려** "몇 시에·어떤 종목을 살 뻔했는지" 로그로 확인. 돈 안 들이고 검증. (S-Oil우·코스맥스엔비티 같은 실사례로 대조.)

**2단계 — 검증되면 실봇 연결.**
`runner.py`에 `--broad` 옵션 추가 → 넓은 목록으로 실제 매수(dryrun → live 이중게이트 그대로).

## 5. 거래량 "터짐" 기준

1단계에선 **기존 신호 그대로 시작** — 동시간대-대비 누적 페이스(`vol_curve` + `VOL_PACE_MIN`). 관찰 로그를 보며 문턱/정의를 튜닝한다. (추후 "최근 N분 급증" 같은 순간 스파이크 신호로 개선 가능 — **이번 범위 밖**.)

## 6. 제약 — 조회 부하

감시 종목이 수십~수백 개로 늘면 KIS 조회 한도가 걸릴 수 있다.
- 구현 착수 시 **실제 종목 수를 먼저 센다.**
- 필요하면 폴링 주기(`POLL_SEC`)·배치 조회·종목 상한으로 맞춘다.
- 관찰(1단계)은 부담이 적어 여기서 실측 후 결정.

## 7. 안전

- 넓은 감시는 **옵트인(`--broad`)** — 기본은 기존 좁은 동작.
- 실매수는 기존 **dryrun 기본 + `--live` 이중게이트** 유지.
- 1단계 관찰기는 주문 코드 미import(읽기 전용).

## 8. 테스트

- `load_watchlist_broad` 순수 함수 단위 테스트: 합성 후보(actionable/forming/breakout/failed, 피벗 유/무, 중복 코드)로 포함·제외·dedup 검증.
- 기존 테스트(signals·replay·watchlist) 무회귀 확인.
- 1단계: 실제 거래일 관찰 로그로 정성 검증.

## 9. 범위 밖 (이번엔 안 함)

- 청산 규칙·슬롯 수 변경 (별도 주제)
- 거래량 순간-스파이크 신호 (기존 누적 페이스로 시작)
- 갭업(+3% 초과 출발) 대응 — 구조적으로 매수 불가, 수동으로도 못 잡음
- 장중 SEPA 전체 재스캔 (피벗은 장중 불변 → 불필요)
- 파워플레이 전체종목(RS80↑) 감시
