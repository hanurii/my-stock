# 거래정지 사유 태깅 — 설계

작성 2026-07-31

## 배경

`liveness.py`는 최근 5거래일 연속 거래량 0을 거래정지로 보고 유니버스에서 뺀다.
이 규칙 자체는 정확하다 — 2026-07-31에 정지 판정 194종목을 전부 네이버 실제
시세와 대조한 결과 **오탐 0건**이었다(거래량 0으로 찍힌 날은 실제로도 무거래,
동결 가격도 실제와 일치).

문제는 **사유가 섞여 있다**는 점이다. 주식분할로 사흘 멈춘 나이스정보통신과
상장적격성 실질심사에 걸린 덱스터가 똑같이 "거래정지"로만 취급된다. 게다가
현재 `dropped` 목록은 콘솔에 개수만 찍히고 **어디에도 저장되지 않아**, 나중에
"이 종목이 왜 후보에 안 나왔지?"를 되짚을 수 없다.

DART 공시 제목에 사유가 그대로 박혀 있어 기계 판별이 가능하다:
`주권매매거래정지 (주식분할)`, `주권매매거래정지 (주식의 병합, 분할 등 전자등록 변경, 말소)`.

## 목적과 범위

**목적: 진단 기록.** 제외된 종목과 그 사유를 파일로 남겨 사후에 확인할 수 있게 한다.

**제외 규칙(행동)은 바꾸지 않는다.** 이유가 셋이다.

1. 오탐이 0건이라 고칠 것이 없다.
2. 제외는 자동 복구된다 — `is_halted`가 매 실행 다시 계산하므로 거래가 재개되면
   다음 실행에 저절로 복귀한다. 영구 제외가 아니다.
3. 정지 중엔 어차피 매수할 수 없다. 일시 정지 종목을 예외로 유니버스에 남기면
   오히려 기준가가 바뀐 깨진 시세로 후보에 오를 위험만 생긴다
   (2026-07-31 금호전기 +360% 사고 — `--repair-rebase` 로 해결한 그 문제).

## 구성

### 새 모듈 `scripts/canslim_lib/halt_reason.py`

| 함수 | 역할 | 의존 |
|---|---|---|
| `classify_halt_reason(reports)` | 공시 (날짜, 제목) 목록 → `{kind, label, report}` | 없음(순수 함수) |
| `fetch_halt_reason(code, corp_map, halt_started)` | 캐시 확인 → 미스면 DART 조회 → 분류·저장 | DART, 파일 캐시 |
| `annotate_dropped(dropped, get_series)` | 제외 목록에 정지 기간·사유를 붙여 반환 | 위 둘 |

`classify_halt_reason`이 순수 함수인 것이 핵심이다. 분류 규칙은 실수하기 쉬운
부분이라(아래 참조) 실제 공시 제목 픽스처로 단위 테스트한다.

### 분류 규칙

`주권매매거래정지 (사유)` 제목의 **괄호 안**을 1순위로 본다. 순서대로:

1. `해제`가 포함된 정지 공시가 더 최근이면 → `unknown`(이미 풀림, 곧 재개)
2. 괄호 사유가 병합·분할·감자·합병·스팩합병·전자등록 변경 → `temporary`
3. 상장적격성·상장폐지·관리종목·감사의견·회생·파산·횡령·배임 → `serious`
4. 해당 없음 → `unknown` (억지로 분류하지 않는다)

**왜 괄호를 우선하나:** 조사 중 제목 전체를 키워드로 훑었더니 CSA 코스믹이
오분류됐다. `주권매매거래정지해제 (감자 주권 변경상장)`인데 다른 공시의
키워드에 걸려 '심각'으로 잡혔다. 한 종목의 공시 목록에는 상반된 사건이 섞여
있으므로, 가장 명시적인 신호(정지 공시의 괄호)를 먼저 봐야 한다.

### 캐시

`.cache/halt_reason/<코드>.json` — `{code, kind, label, report, halt_started, fetched_at}`

`halt_started`(마지막 거래일 다음 영업일)가 캐시와 다르면 **새로운 정지**로 보고
재조회한다. 같으면 그대로 쓴다. 평소 하루 0~5건만 조회되고, 첫 실행만 ~170건.

### 산출 `public/data/sepa-halted-stocks.json`

```json
{
  "generated_at": "2026-07-31 21:40",
  "asof": "2026-07-31",
  "counts": {"total": 170, "temporary": 35, "serious": 7, "unknown": 128, "manual": 1},
  "stocks": [
    {"code": "036800", "name": "나이스정보통신", "reason": "halted",
     "zero_days": 3, "last_trade": "2026-07-28",
     "kind": "temporary", "label": "주식분할",
     "report": "주권매매거래정지 (주식분할)"}
  ]
}
```

`reason`은 기존 `liveness`의 값(`halted` 자동감지 / `excluded` 수동목록)을 그대로
쓴다. `kind`는 새로 붙는 사유 분류다. 둘은 다른 축이므로 이름을 분리한다.

### 붙는 자리

`screen_trend_template.run_full_scan`의 `filter_live_universe` 직후 — 이미
`dropped`를 계산하는 그 지점. 파이프라인 순서(`/sepa`)는 바뀌지 않는다.

## 실패 처리

DART 조회 실패·키 없음·`corp_code` 미매칭은 전부 **비차단**이다. `kind: "unknown"`
으로 기록하고 넘어간다. 정지 기간·마지막 거래일은 캐시에서 나오므로 DART가 완전히
죽어도 파일은 정상 생성된다.

## 테스트

- `classify_halt_reason` — 실제 공시 제목 픽스처(나이스정보통신 주식분할, 코미코
  분할, 덱스터 상장적격성, CSA 코스믹 정지해제, 스팩 합병, 공시 없음)
- 캐시 무효화 — `halt_started`가 바뀌면 재조회하고, 같으면 캐시를 쓴다
- `annotate_dropped` — DART가 죽어도 정지 기간은 채워지고 `kind`만 `unknown`

## 안 하는 것

웹페이지 표시 · 보유 종목 정지 경고 · 재개 임박 워치리스트 · 제외 규칙 변경.
진단 기록이 목적이므로 전부 범위 밖이다.
