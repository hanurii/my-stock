- 회귀: 플래그 없는 실행의 candidates/failed_stocks 는 종전과 완전 동일,
  ipo 키도 미생성. 마키나락스는 failed_stocks 에도 그대로 유지(이중 기록 의도).

## 배경 — 왜 필요한가

현재 관문(트렌드 템플레이트)은 상장 이력이 짧은 종목을 구조적으로 완전히 무시한다
(2026-08-08 코드 조사, 파일:라인 실측):

- **200거래일 게이트**: `screen_trend_template.py:72` `MIN_CLOSES_FOR_TT=200`,
  135~141행 — 보유 종가 <200이면 평가 없이 `failed_stocks` 직행("데이터 부족").
- **RS 산출은 사실상 253거래일부터**: RS는 ok(≥200일) 종목만 계산(178행).
  200~252일 구간은 단축 윈도우(win=n-1)를 지원하나 비교풀이 "정확히 같은 win"
  종목뿐이라(209~210행) 풀<100 → RS=None(228~235행) → 조건8 자동 탈락
  (`trend_template.py:195-197`).
- **조건3(200MA 1개월 상승)은 222거래일 필요**(`trend_template.py:141-148`).
- **하위 패턴 스킬은 all_pass만 읽음**(`screen_vcp.py:43` 등) — failed_stocks에만
  있는 신규상장은 VCP/3C/파워플레이 어디에도 도달 못 함.

결과: 마키나락스처럼 상장 2~3개월 된 강한 종목은 **상장 1주년 무렵(253거래일)까지
실질 후보 불가**. 그러나 미너비니·오닐은 신규상장을 적극 매매한다 — 상장 후 첫
베이스(**primary base**, 최소 3~5주)를 돌파하는 IPO가 대시세의 단골 출발점이라는
게 두 사람의 공통 관찰이다. 현 구조는 이 유형을 0% 커버한다.

## 목표 / 비목표

**목표** — 상장 20~199거래일 종목을 기존 트랙과 **분리된 "IPO 트랙"**으로 평가해:
1. 페이지에 노출(🐣 배지 + 상장 일수), 2. 패턴 검출(가능한 것만) 연결.
기존 8조건 트랙 산출(candidates/failed_stocks)은 **1바이트도 안 바뀐다**(오염 금지).

**비목표(1단계)** — 매수 추천 채점 편입(초수익 점수 검증 표본에 IPO 없음),
자동매수 봇 연동, 백테스트로 파라미터 확정(과거 IPO as-of 재현은 검증 계획에서).

## 설계

### 1) IPO 트랙 대체 템플레이트 (상장 20~199거래일 대상)

기존 8조건의 "정신"을 짧은 데이터로 번역한 7조건:

| # | 조건 | 대응 원조건 | 비고 |
|---|---|---|---|
| I1 | 종가 > 50일MA (50일 미만이면 가용 전체 MA) | 조건1·2 (가격>150·200MA) | |
| I2 | 그 MA가 최근 22일(데이터 짧으면 가용 절반) 상승 | 조건3 (200MA 1개월 상승) | |
| I3 | 상장 후 최저가 대비 **+25% 이상** | 조건6 (52주 저가 +30%) | IPO 초기 변동 감안 완화 |
| I4 | 상장 후 최고가 대비 **-25% 이내** | 조건7 (52주 고가 근접) | 코드가 이미 가용 전체로 폴백(`trend_template.py:108`) |
| I5 | **ipo_rs ≥ 80** — 아래 별도 정의 | 조건8 (RS≥80) | 기존 `rs` 필드와 분리 |
| I6 | 미너비니 필터 통과 | (관문 공통) | 20일 이상이면 판정 가능(`minervini_filter.py:37`) |
| I7 | 상장 ≥20거래일 | — | primary base 최소 3주 + 필터 판정 하한 일치 |

**ipo_rs 정의**: 최근 `min(n-1, 60)`거래일 수익률을 **전 종목 동일 창(60일) 수익률
분포의 percentile**로 환산. 전 종목 시계열이 이미 메모리에 있으므로 "같은 win끼리만
비교" 제약을 우회 — 신규상장이 몇 종목이든 시장 전체와 비교된다. 기존 RS(1년 가중)와
다른 물건이므로 **필드명 분리(`ipo_rs`)** + 페이지 표기도 "iRS"로 구분.

### 2) 산출 스키마 — 기존 파일에 새 배열, 기존 키 불변

`sepa-trend-candidates.json`에 `ipo_candidates` 배열 추가:
`{code, name, market, listed_days, first_date, ipo_rs, criteria(I1~I7), all_pass, extras}`.
기존 파서(하위 스킬·페이지·태깅)는 모르는 키를 무시하므로 하위 호환.

### 3) 하위 패턴 연결 — opt-in

- `screen_vcp/3c/power_play --include-ipo` 플래그: `ipo_candidates` 중 all_pass도
  읽는다. 패턴 미검출은 자연스러운 결과(아직 베이스가 없음) — 검출기 수정 없음.
- 파워플레이는 깃대 14주(70일) 요구라 상장 70일+부터 의미 있음(플래그 동일, 자연 탈락).

### 4) 페이지 표시

- 1단계 요약에 "IPO 트랙 통과 N종목" 한 줄.
- 후보 테이블에 🐣 배지(`🐣55일` 형태) — 새 섹션은 만들지 않음(1단계).

### 5) 파라미터 정본

`IPO_MIN_DAYS=20 · IPO_RS_WINDOW=60 · IPO_RS_MIN=80 · IPO_LOW_GAIN=25 ·
IPO_HIGH_DIST=25` — `screen_trend_template.py` 상수로 시작(관문 파라미터는 해당
모듈이 정본), 필요시 CLI 노출.

## 리스크와 보수 장치

- **보호예수 해제·초기 급변동 → 오탐**: 1단계는 표시만(추천 채점 제외).
  `track_buy_recommendations` 방식의 원장에 ipo 트랙을 별도 기록해 몇 달 전방
  성과를 쌓은 뒤 승격 여부 판단(살아있는 검증).
- **파라미터 근거 부족**: I3/I4의 25%는 시작값 — 아래 회고 검증으로 보정.
- **ipo_rs ≠ RS 혼동**: 필드·표기 분리로 차단. 통합 요약에도 "iRS" 표기.
