# 266 - 야후만으로 굴러가나, 그리고 원자료가 어디까지 있나

> 조사 세션 2026-09-10 · `research/handoff/scripts/266-yahoo-only.py`
> 아직 아무것도 짓지 않았다. 시험만 했다.

---

## 0. 먼저 — 원자료가 10.2년치뿐이다

```
`.cache/sharadar/stocks-10Y.csv.zip` 를 통째로 훑었다.

행 15,951,160 · 제일 이른 날 2016-06-30 · 제일 늦은 날 2026-09-09

27.4년 백테스트가 쓴 1999~2016 구간의 원가격은 디스크에 없다.
남아 있는 것은 그것으로 만든 경로 파일뿐이다(`D:/stock-data/uspath-rs70/` 등 해마다 하나씩 28개).

10월이 되면 2016-06-30 앞을 다시 낼 길이 없어진다.
```

### 이것이 바로 걸리는 곳

지금 미측정으로 남은 것 중에 그 구간을 필요로 하는 것이 있다.

- 우리와 지수의 해마다 격차 신뢰구간을 현행 규칙으로 다시 내는 일(`152-resolution.py:40` 이 +20/-10 으로 박혀 있다).
  이건 오늘 최종 검증에서 「안 쟀다」로 남긴 항목이다.
- 우리 연수익 SD 와 상관을 갈라 내는 일(`263-sd-sensitivity.md` 에서 경계로만 가뒀다).

둘 다 27.4년 구간이 있어야 한다. 10월 뒤에는 못 한다.

### 정정

앞서 `264` 와 `265` 에서 Sharadar 가 2026-08-21 에 끝난다고 적었다.
그 뒤 오늘 21시 무렵에 자료가 갱신돼 지금은 2026-09-09 까지다.
두 문서의 이음매 수는 갱신 전 판의 것이다. 지우지 않고 여기에 새 수를 적는다.

| | 갱신 전 | 갱신 후 |
|---|---|---|
| Sharadar 마지막 날 | 2026-08-21 | **2026-09-09** |
| 이음매 창 | 13~14거래일 | **1거래일** |
| 그 창 안의 분할 | 29개 | **1개 (LFT · 2026-09-10 · 1대 10)** |

갱신 전에 찾은 29개 중 28개는 이제 Sharadar 안으로 들어왔다.
APH 2대1 분할도 그 안에 든다.

이 수가 말하는 것은 하나다. 자주 갱신하면 이음매 문제가 거의 사라진다.
그리고 10월부터는 갱신이 멈추므로 창이 날마다 커진다.

## 1. 야후가 얼마나 긴 역사를 주나

30종목을 대형·중형·소형으로 섞어 period=max 로 받았다. 3.0초 걸렸다.

우리 규칙에 필요한 제일 긴 창은 RS 의 252거래일과 이평의 200일이다.
웜업까지 보면 1.5년(378거래일)이면 된다.

| 무엇 | 값 |
|---|---|
| 378거래일 이상 주는 종목 | **30 / 30** |
| 10년 이상 | 19 / 30 |
| 제일 긴 것 | XOM · KO · CAT · 1962-01-02 부터 · 16,280행 |
| 제일 짧은 것 | KAPA · 2024-09-16 상장 · 497행 |

짧은 것들은 야후가 못 준 것이 아니라 상장한 지 얼마 안 된 것이다.

```
답: 야후 역사만으로도 우리 규칙은 굴러간다.
```

다만 「굴러간다」와 「27.4년 검증이 그대로 옮겨진다」는 다르다.
검증은 Sharadar 자료 위에서 했고, 두 자료의 규약 차이는 아직 다 재지 않았다.
`264` 에서 분할 종목 열 개 중 둘이 어긋났다. 표본이 열뿐이라 비율은 못 쓴다.

## 2. tickers.csv 를 무엇으로 대신하나

Sharadar 가 주는 것과 대신할 것을 나란히 놓는다.

| Sharadar 가 주는 열 | 나스닥 공개 목록 | 야후 info | 비고 |
|---|---|---|---|
| exchange | 있음 | 있음 | 둘 다 됨 |
| ETF 여부 | 있음 | quoteType 으로 됨 | |
| 테스트 종목 | 있음 | 없음 | |
| sector · industry | 없음 | **있음** | 야후가 메운다 |
| category (우선주·ADR·2차클래스) | 없음 | **확인 안 됨** | quoteType 은 전부 EQUITY 였다 |
| siccode (SPAC 6770) | 없음 | 없음 | **메울 것이 없다** |
| isdelisted | 없음 | 없음 | 목록에서 사라지는 것으로 유추해야 한다 |
| firstpricedate | 없음 | 역사 첫날로 대신 | |

야후 info 를 10종목에서 뽑아 봤다. 빈 값은 이랬다.

```
quoteType            빈 값 0 / 10
exchange             빈 값 0 / 10
sector               빈 값 0 / 10
industry             빈 값 0 / 10
marketCap            빈 값 0 / 10
sharesOutstanding    빈 값 0 / 10
currency             빈 값 0 / 10
```

열 개에서는 하나도 안 비었다. 다만 열 개다. 전수가 아니다.

```
메울 수 있는 것: 거래소 · ETF · 업종 · 시가총액
메울 수 없는 것: SPAC 을 가르는 SIC 코드 · 우선주와 ADR 과 2차 클래스를 가르는 분류

그리고 10월부터 tickers.csv 갱신이 멈추면 신규 상장이 유니버스에 안 들어온다.
나스닥 공개 목록이 그것을 메울 수 있으나, 위 두 가지는 못 메운다.
```

### 비용도 다르다

야후 info 는 종목마다 따로 호출해야 한다. 10종목에 8.0초 걸렸다.
4,039종목이면 선형으로 잡아도 약 54분이다. 날마다 돌릴 것이 못 된다.
업종 같은 것은 자주 안 바뀌므로 가끔만 받으면 되지만, 그건 설계에서 정할 일이다.

## 3. 야후가 막히나

200종목을 1년치로 한 번 받았다. 더 크게 시험하지 않았다.

| 무엇 | 값 |
|---|---|
| 걸린 시간 | 6.6초 |
| 200행 넘게 받은 종목 | 192 / 200 |
| 짧게 온 8개 | 상장한 지 얼마 안 된 것들이다. 받기 실패가 아니다 |
| 4,039종목 선형 어림 | 약 2.2분 |

오늘 실측이 둘 더 있다. 4,039종목 3.4개월치를 137초에 받았고,
분할 사건만 훑는 데 192초 걸렸다. 셋이 서로 어긋나지 않는다.

막히는 것은 못 봤다. 다만 요청 한도에 걸린 것이 한 번 있었다(MOG.A).
점 붙은 티커는 야후에서 따로 다뤄야 한다. BF.B · BRK.B · CRD.A · MOG.A 가 그랬다.

## 4. 무엇을 지금 해야 하나

정하는 것은 내 몫이 아니다. 수만 놓는다.

- 9월 마지막 거래일 뒤에 한 번 더 받으면 이음매 창이 다시 1거래일이 된다.
  오늘 갱신으로 29개가 1개가 된 것이 그 증거다.
- 더 긴 역사를 받는 것은 값어치가 있다. 지금 디스크에 10.2년치뿐이고,
  10월 뒤에는 2016-06-30 앞을 다시 낼 길이 없다.
  아직 안 잰 것 둘이 그 구간을 필요로 한다.

## 이 판이 못 한 것

- 역사 길이는 30종목, info 는 10종목, 규모는 200종목만 봤다. 전수가 아니다.
- 야후 info 가 우선주와 ADR 과 2차 클래스를 가를 수 있는지 확인 못 했다.
  표본에 그런 종목이 없었다. 「없다」가 아니라 「안 봤다」다.
- 야후와 Sharadar 의 규약 차이를 다 재지 않았다. 분할 열 개 중 둘이 어긋난 것까지다.
- 상장폐지 종목을 야후에서 받을 수 있는지 안 봤다. 백테스트에 상폐가 1,603개 들어 있다.
- 「10.2년치뿐」은 디스크에 있는 파일 기준이다. 사용자가 더 받을 수 있는지는 모른다.
