## 1. 소비자가 읽는 키 — 전수로 셌다

찾은 범위를 먼저 적는다.

```
scripts/screen_trend_template.py
scripts/canslim_lib/trend_template.py
scripts/canslim_lib/vcp.py · power_play.py · cheat.py · ipo_track.py
```

검출기 셋은 `series.get("...")` 로 꺼내고, 화면 스크립트는 `mtx["..."]` 로 읽는다.
추세 판별기와 IPO 트랙은 series 를 통째로 받지 않고 리스트를 인자로 받는다.

| 키 | 누가 읽나 | 만들어야 하나 |
|---|---|---|
| `dates` | vcp · power_play · cheat · screen_trend_template | **예** |
| `opens` | vcp | **예** |
| `highs` | vcp · power_play · cheat | **예** |
| `lows` | vcp · power_play · cheat | **예** |
| `closes` | vcp · power_play · cheat · screen_trend_template | **예** |
| `volumes` | vcp · power_play · cheat | **예** |

```
만들어야 할 키는 일곱이다.
```

앞선 실측에서 `timestamps` 를 빠뜨렸다. 이번에는 넣고 쟀다.

## 2. 넉넉히 자르고 다듬기 — 실측

고정 날짜 문턱을 버렸다. 24개월치를 넉넉히 자른 뒤
종목마다 마지막 310봉만 남기는 방식이다.
그러면 「몇 개월이면 되나」를 고를 일이 없어진다.

| 무엇 | 값 |
|---|---|
| 날짜 문턱 | 2024-09-01 (24개월) |
| 남긴 행 | 3,110,630 / 45,317,834 (6.86%) |
| 종목 수 | 7,398 |
| 다듬기 전 종목당 봉 | 중앙 506 · 최대 506 |
| **추리기 (세 번 중앙)** | **54.3초** |
| **다듬기 + timestamps** | **26.3초** |

세 번 값은 66.1 · 54.3 · 51.7 초였다. 중앙을 쓴다.

```
여유가 506봉이다. 필요한 것이 310 이므로 196봉이 남는다.
휴장일이 얼마나 끼든 모자랄 일이 없다.
```

### 뜻밖의 것 — 문턱을 넓혀도 시간이 안 늘었다

| 문턱 | 남긴 행 | 종목 | 추리기 |
|---|---:|---:|---:|
| 2025-06-01 (12개월) | 1,979,932 (4.37%) | 6,905 | 53.3초 |
| 2024-09-01 (24개월) | 3,110,630 (6.86%) | 7,398 | 54.3초 |

남긴 행이 1.6배가 됐는데 시간은 같다.
병목이 파싱이 아니라 4,530만 줄을 읽어 내려가는 것 자체이기 때문이다.

이건 내 어림이 왜 계속 틀리는지도 말해 준다.
나는 60~80초로 봤다. 바닥을 재고 곱하는 쪽으로 바꿨는데도 과대였다.
곱할 것이 거의 없었던 것이다. 열 번 중 아홉 번을 과대로 잡았다.

### 다듬기가 생각보다 비싸다

다듬기와 timestamps 만들기에 26.3초가 든다. 추리기의 절반이다.
날짜 문자열마다 `time.strptime` 을 부르기 때문이다.
날짜가 종목마다 겹치므로 한 번만 바꿔 두고 돌려쓰면 줄어들 것이다.
그건 어림이다. 재지 않았고 고치지도 않았다.

## 3. 저장 — json 한 덩어리

| 무엇 | 값 |
|---|---|
| 디스크 | **114 MB** |
| 쓰기 (세 번 중앙) | 4.8초 |
| 읽기 (세 번 중앙) | 3.5초 |

세 번씩 쟀다. 쓰기 4.8 · 4.5 · 7.9 초, 읽기 3.5 · 2.8 · 8.4 초였다.

마지막 한 번이 다른 둘보다 두 배 가까이 느렸다.
같은 코드로 같은 자료를 잰 것이므로 기계 쪽 사정이다.
한 번만 쟀다면 이걸 못 봤을 것이다.

앞선 판에서 json 이 pickle 보다 작고 빠르다고 적었는데,
그건 한 번씩만 잰 값이었다. 이번 세 번으로 보면 편차가 그 차이만큼 크다.
그러니 「json 이 더 빠르다」는 이 수로는 말할 수 없다.
작다는 것은 그대로다.

## 4. 310봉을 채우는 종목

| 무엇 | 값 |
|---|---|
| 310봉을 채운 종목 | 5,858 / 7,398 (79.2%) |
| 못 채우는 종목 | 1,540 |

12개월 문턱에서는 79.9% 였고 24개월 문턱에서는 79.2% 다.
비율이 거의 같다. 문턱을 넓혀도 못 채우는 종목은 그대로다.
창이 짧아서가 아니라 그 종목들이 짧기 때문이다.

종목 수는 6,905 에서 7,398 으로 늘었다. 창이 길어지며 그 안에서 상장폐지된 것이 더 들어왔다.
신규 상장인지 상장폐지인지 가르는 것은 유니버스 판의 일이라 여기서 안 했다.

## 이 판이 못 한 것

- `time.strptime` 을 한 번만 부르게 고치면 얼마나 빨라지는지 안 쟀다.
- pickle 을 세 번으로 다시 재지 않았다. json 쪽만 세 번 쟀다.
- 야후 꼬리를 어떻게 붙일지는 이 판 밖이다.
- 못 채우는 1,540개를 신규와 상폐로 안 갈랐다.
- 24개월이 넉넉하다는 것은 오늘 자료 기준이다. 다음에 다시 재야 한다.
