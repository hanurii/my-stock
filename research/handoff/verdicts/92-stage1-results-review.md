## 1. ★★ ㉢ — **잠정 판단이 «부족»하다. 그리고 답의 절반이 이미 있다**

```

dilution 5분위  주식 수 **+27%/년**      → 대규모 증자
```
**둘 다 「작고 변동이 큰 회사」의 정의에 가깝다.** 그리고 **잰 것은 MFE 다.**

🚨 **86번이 확정한 것**: MFE 문턱은 «변동 폭»이 직접 올린다.

### 1-2. 그래서 «먼저» 할 것 — **슬롯 시뮬이 아니라 «겹침 측정»**

`dilution 5분위` ∩  같은 것

- **크게 겹치면** → 92 는 «새 발견»이 아니라 **같은 발견의 새 이름**이다.

> **86번에서 이 측정 한 줄이 「1·2등이 한 발견」을 갈랐다.** 여기서도 같은 한 줄이다.

### 1-3. 그리고 **한계가 하나 더 있다 — 상장폐지**

## 5. ㉤ — **헐거워진 게 아니다. 그런데 «진짜 물음»이 하나 숨어 있다**

### 5-1. 곱셈 문턱 자체는 «옳다»

```
기준율 × 1.5  →  **배수를 고정** = 척도 불변
덧셈(+5%p)    →  기준율이 낮은 창에서 훨씬 어려워진다 = 창마다 «다른 자»
```
**기준율이 7.46% 인 창과 13.26% 인 창을 «같은 자»로 재려면 곱셈이 맞다.**
→ **등록 의도대로 작동한 것이고, 조용히 헐거워진 게 아니다.** ✅

### 5-2. 🚨 그런데 **검정력은 척도 불변이 아니다**

```
판정① ㉯  기준율 7.46% · 상위분위 n≈1,539 → **사건 ≈115건**
판정② ㉯  기준율 13.26% · n≈2,815      → **사건 ≈373건**
```
**같은 배수 문턱이라도 판정①에서는 잡음이 훨씬 크다** → **그 문턱에서의 거짓통과율이 높다.**
**「자」는 같은데 «오차»가 다르다.**

> ### **그래서 진짜 물음은 이것이다: 「N★(순열 귀무)이 판정 «두 창 각각»에서 계산됐는가?」**
> - **창별로 계산됐다** → 각 창의 실제 잡음이 반영되므로 **5-2 는 자동으로 교정된다.** 문제 없음. ✅
> - **한 창에서만(또는 합본으로) 계산됐다** → **다른 창은 «고정 바»만 걸린 것**이고,
>   거기서 낮은 기준율이 **실제로 문턱을 헐겁게 만든다.** 🚨
>
> 보고서에 N★ 이 **한 줄**로만 적혀 있어(「관측 +5.23 vs 귀무 4,000판 최대 +3.46」)
> **어느 창의 것인지 안 보인다. 창별로 나눠 찍으시라.** 그게 ㉤ 의 답이다.

등록 판정은 통과로 두고 적어만 둔 것 — **§3 에서 그은 선(서술 결과로 결론을 바꾸면 그 순간 검정)을
두 번 말하지 않아도 지켰다.**

### 🚨 다만 층화 표에 **한 줄이 빠졌다 — 칸별 n**

```
①조용 −0.41/−0.08 · ②보통 **+4.87/+4.99** · ③큼 **+3.82/+4.44** · ④매우큼 −7.32/−0.63

## 9. 물으신 셋

### 9-1. 🚨 상폐가 슬롯 시뮬에서 어떻게 결착되나 — **찾았다**

`41-round1-exits.py:resolve_half_then_trail` 의 마지막 줄:
```python
return (d[n-1], "unresolved", [(d[n-1], 1.0, g(c[n-1]))], True, [("미결", None, g(c[n-1]))])
```
> ### **목표·손절 어느 것도 안 닿고 경로가 끝나면 → «마지막 종가»로 전량 결착. `at_end=True` · `result="unresolved"`.**

**그러니 「빠지는」 게 아니라 「마지막 프린트로 정산」된다.** 손실이 사라지지는 않는다. ✅
🚨 **그런데 «적자 회사»에서는 그게 낙관 쪽이다:**
```
파산 경로는 대개  거래정지 → 상폐  로 가고, **마지막 프린트는 «0 이 아니다»**
→ 상폐 후 잔존가치(대개 0 에 가까움)와의 «차이»만큼 우리 장부가 후하게 잡힌다
```
**방향: 적자·희석 칸에 «유리»하게 치우친다.** 92 의 통과 칸이 바로 그 칸이다.

> ### ★ **그리고 이걸 재는 자가 «이미 있다»** — `41` 이 `at_end_pct` 를 계산한다(322행).

### 9-2. N★ 을 창별로 나눠 찍는 재실행 — **서술이 맞다. 그런데 «안 해도 된다»**

**서술 판정은 맞다** — 등록 통계를 쪼개 찍는 것이고 선택을 다시 하는 게 아니다.
**단 조건 하나**: **「이 분해는 «해석»을 바꾸되 «판정»은 안 바꾼다」를 «먼저» 적으시라.**
(dilution 에서 이미 그렇게 하셨다. 같은 선이다.)

🚨 **그런데 내 ㉤ 걱정이 설계로 «이미» 답해져 있었다:**
```
통계량 = min(판정①lift, 판정②lift)  ·  귀무도 «같은 min»
→ 두 창을 «둘 다» 넘어야 하고, 잡음이 큰 창은 min 을 통해 «스스로 벌점»을 받는다
→ 창별 본페로니가 하려던 일을 **min 이 이미 더 잘 하고 있다**
```
**내가 「고정 바만 걸린 창이 헐거워진다」고 걱정한 상황이 min 구조에서는 안 생긴다.**
→ **㉤ 때문에 재실행할 필요는 없다.** ㉠(2017 걸침)도 **보수적**이라 필요 없다.
> **판정 창을 아끼시라. 다른 이유로 돌릴 일이 생기면 그때 둘을 얹으면 된다.**
