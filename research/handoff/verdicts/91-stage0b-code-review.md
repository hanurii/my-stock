## 1. ① seed 짝맞춤 — **맞다. 그리고 근거가 «seed 번호»가 아니다**

```python
def sim(ev, n_seed):
    return [sl.sim_lots(ev, seed=s, ...) for s in range(n_seed)]
raw = [x["equity_pct"] for x in rs]
```
리스트 컴프리헨션이 `range(n_seed)` 를 도므로 `raw[s]` 는 **seed s** 다. ✅ 순서 보존.

### ★ 그런데 «훨씬 더 좋은» 이유가 있다 — `order_key` 가 «거래별»이다

```python
# slot_sim.py:55
def order_key(seed, t):
    return random.Random("%d|%s|%s|%s"
                         % (seed, t["code"], t["scan_date"], t["pattern"])).random()
```
**난수 키가 (seed, 거래 신원)에 걸려 있다.** 그래서 **같은 seed 면 같은 거래는 어느 사다리에 있든 «같은 키»**를 받는다.
그리고 `lvl2 ⊆ lvl1 ⊆ by0` 로 **포개져 있으므로**, 세 칸이 공유하는 거래는 **상대 순서가 그대로 유지된다.**

> ### **즉 세 칸이 나눠 갖는 것은 「seed 번호」가 아니라 «추첨 그 자체»다.**
> **이건 짝비교로 만들 수 있는 가장 강한 형태다.** `slot_sim.py:56-57` 주석이 이걸 의도했다고 적어 뒀다.
> → **D★ 의 `r0["raw"][s] < r1["raw"][s] < r2["raw"][s]` 는 «올바를» 뿐 아니라 «최선»이다.**

**부수 확인**: 세 칸의 `yrs` 가 같으므로 `cagr` 는 총수익의 단조변환이다.
→ `equity_pct` 로 순서를 세는 것과 「연환산」으로 세는 것이 **정확히 같다.** 사전등록 문구와 안 어긋난다. ✅

## 2. ② `boot_ci` — **맞다**

```python
meds.append(st.median(vals[rnd.randrange(n)] for _ in range(n)))   # n개 복원추출 → 중앙값
meds.sort(); return meds[int(b*2.5/100)], meds[int(b*97.5/100)]
```
**n 개 복원추출 → 중앙값 → 4,000회 → 2.5/97.5 백분위.** 정통 중앙값 부트스트랩이다. ✅
난수 고정(`seed=0`)도 되어 있다. `st.median` 은 제너레이터를 받는다(내부에서 `sorted`). ✅

## 3. 🚨 안 물으신 데서 — **셋**

### 3-1. `E` 의 MDE 가 **중앙값이 아니라 «평균»의 표준오차를 쓴다** (약 20% 낙관)

```python
sd  = st.pstdev([cagr(x, r2["years"]) for x in r2["eq"]])
mde = 2.8 * sd / math.sqrt(n_seed)
```
- **`2.8` 은 맞다** — `z₀.₉₇₅ + z₀.₈₀ = 1.96 + 0.84`, 표준 MDE 배수다. 여기는 문제없다.
- 🚨 **`sd/√n` 은 «평균»의 표준오차다.** 그런데 비교 대상 `bmed` 은 **중앙값**에서 나왔다
  (`r2["cagr"] = cagr(median(eq), yrs)`).
- 정규 근사에서 **중앙값의 표준오차는 평균의 1.253배**다.
  → 옳은 값은 `2.8 × 1.253 × sd/√n ≈ 3.51 sd/√n`. **지금 값은 약 20% 작다 = 낙관 쪽.**
  → 「가릴 수 있는 크기」를 **실제보다 쉽게** 찍는다.

> ### **처방(공짜) — `boot_ci` 가 이미 있다.**
> **중앙값의 «진짜» 표준오차는 `boot_ci` 폭에서 바로 나온다**(정규 가정도 필요 없다):
> `SE ≈ (hi − lo) / 3.92`  →  `MDE = 2.8 × SE`
> **같은 함수를 두 자리에 쓰면 자가 하나로 통일된다.**
> ⚠️ 크기는 20%라 판정이 뒤집힐 자리는 아니다. **다만 「자를 맞춘다」는 이 프로젝트 규약이다.**

### 3-2. `C★` 의 MAR 이 **«중앙값끼리의 비»**다 (중앙 MAR 이 아니다)

```python
mar = abs(r2["med"] / r2["mdd"])     # 중앙자산 ÷ 중앙MDD
```
**두 중앙값의 «비»는 비의 중앙값이 아니다.** 분포가 치우치면 값이 달라진다(유형 3 사촌).
벤치마크 쪽은 경로가 하나라 정확하므로 **자가 한쪽만 흔들린다.**

> **처방: 등록된 통계는 «그대로 두시라»**(81 의 14.42 와 이어져야 한다).
> **라벨만 붙이고**(`MAR = 중앙자산 ÷ 중앙MDD`), 옆에 **`median(|eq_s / mdd_s|)`** 를 «참고»로 찍으시라.
> `rs` 에 이미 다 있으니 **공짜**다. 둘이 크게 다르면 그 자체가 읽을 거리다.

### 3-3. `A★` 의 «연수»가 두 쪽에서 다르게 계산된다

```python
전략   yrs = (_ord(d1) - _ord(d0)) / 365.25          # 창의 «경계»
벤치마크 yrs = (_ord(ds[-1]) - _ord(ds[0])) / 365.25  # 실제 자료가 «있는» 날
```
자료가 창을 다 덮으면 며칠 차이라 무시할 만하다. **그러나 덮개가 짧으면 조용히 어긋난다**
(예: 벤치마크 계열이 2000년부터면 1999 창에서 «1년» 어긋난다 — 연환산 비교가 그만큼 망가진다).
> **처방(공짜): `assert abs(전략yrs − 벤치yrs) < 0.05` 를 넣으시라.** 지금은 괜찮을 «것»이지만
> **그 「괜찮을 것」이 검사되지 않고 있다.** 터지면 그때 보면 된다.

## 4. ★ 내가 세운 의심 하나가 **죽었다** — 그리고 그게 D★ 를 «구한다»

`lvl1` 의 첫 줄이 이렇다:

**섹터 라벨이 없으면 그 경로는 사다리 ①② 를 «통째로» 지나간다.**

그러면 D★ 가 전략이 아니라 «자료 덮개»를 재게 된다.**
