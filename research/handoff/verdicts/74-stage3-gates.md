## 1. 🚨 관문 ② 미통과 — **원인을 갈랐다. 「엉뚱한 걸 고친 것」이 아니다.**

사전등록 §6 은 「여기가 깨지면 엉뚱한 걸 고친 것」이라 적었다. **그 읽기는 틀렸다.**

가설: 두 단에서도 갈리는 이유는 «취득가»가 아니라 **«현금 부족으로 막힌 증액을 어떻게 처리하나»**다.
- 옛 `slot_sim_pyr`: 막혀도 청산선은 **「샀다고 치고」** 그대로 둔다 (사전등록 §1②)
- 새 `slot_sim_lots`: 안 산 조합으로 **다시 푼다**(`reslot`)

검정 — 위험을 낮춰 **막힘이 0건**이 되게 만들면 둘이 같아야 한다.

| 판 | 옛 자산 | 새 자산 | 상대오차 | 옛 막힘 | 새 막힘 | |
|---|---|---|---|---|---|---|
| 헤드라인 5칸 20% | +218.24% | +217.90% | 1.598e−01 | 42 | 45 | 다름 |
| 위험 1/10 | +14.0860% | +14.0860% | **0.000e+00** | 0 | 0 | **일치** |
| 위험 1/100 | +1.3432% | +1.3432% | **0.000e+00** | 0 | 0 | **일치** |

> ### **막힘이 사라지면 «정확히» 0 이다. 원인 확정.**
> 두 단의 **취득가 셈은 새·옛이 완전히 같다**(= 두뇌 세션 §1① 의 「두 단은 정확하다」가 맞다).
> 갈리는 것은 **§1② 의 결함을 새 도구가 고쳤기 때문**이다.
> **관문 ② 는 「깨지면 안 되는 관문」이 아니라 「깨져야 하는 관문」이었다.**

**바꿔 쓸 문장:**
```
관문 ②′  「막힌 증액이 0 건인 판」에서 P1 두 단 새 == 옛 (상대오차 < 1e-9)
          ← 이러면 취득가 셈만 대조하고, §1② 를 고친 효과와 섞이지 않는다
```
🚨 이 관문은 **무디지 않다**: 같은 자료·같은 코드로 헤드라인 판에서는 1.598e−01 이 나온다.

## 3. ⚠️ 관문 ④ 는 **실패할 수 없다**

`slot_sim_lots.py` 의 증액 블록에서 `n_add_blocked` 를 올리는 줄은 **«예약 안 함» 가지에만 있다.**
예약 가지는 `take = min(need, h["resv"])` 로 예약분에서 꺼내므로, **코드가 틀려도 0 이 찍힌다.**
→ 두뇌 세션 자기 지적 1(「검사하려던 줄이 한 번도 안 돌았는데 통과」)과 **같은 자리**다.

**대신 잰 것**(P2 수준 방아쇠 · 10판 중앙):
```
예약함     증액 255회 · 막힘 0
예약 안 함  증액 251회 · 막힘 2
→ 예약이 실제로 «더 사게» 만든다 (다만 이 판에서는 +4회뿐)
```
**바꿔 쓸 문장:** `관문 ④′  예약함 판에서 «방아쇠가 난 트랜치 수» == «실제로 산 트랜치 수»`
(지금 코드로는 밖에서 못 센다 — `sim_lots` 이 `fill_log` 를 안 돌려준다. **옛 `slot_sim_pyr` 은 돌려줬다.**
어느 거래가 자본을 받았는지 감사할 길이 사라졌으므로 **되살리기를 권한다.**)

## 5. 청산 축 — 마지막 남은 미검정 축을 닫았다

두 구현이 둘 다 `47-round3-pyramid.py::_phase2` 에서 왔으므로 **세 번째 구현을 또 써도 조상이 같다.**
그래서 방식을 바꿨다 — **산출물이 청산 규칙의 «정의»를 만족하는지**만 본다(성질 검사).
구현을 흉내 내지 않으므로 조상이 같아도 독립이다.

| | 성질 | 대상 | 어긋남 |
|---|---|---|---|
| P1 | 청산 몫 합 == 1.0 | 8,296 | **0** |
| P2 | loss 청산가 == `min(손절선, 시가)` | 6,827 | **0** |
| P3 | win 첫 청산가 == `max(목표선, 시가)` · 몫 0.5 | 1,128 | **0** |
| **P4** | ★ **결착일 «이전»에 더 이른 교차가 없다**(평균단가를 매일 다시 내서) | 8,296 | **0** |
| **P5** | ★ 추격 다리 == `min(max(평단, 직전 25일 최저), 시가)` · 더 이른 교차 없음 | 1,085 | **0** |
| P6 | ambiguous == 같은 날 목표·손절이 둘 다 걸린 날 | 105 | **0** |

**분해능**: 추격 창을 25 → 10 으로 흔들면 **291건 중 273건(93.8%)이 어긋난다.**
→ 0 은 «무딘 검사가 낸 0» 이 아니다.

> ⚠️ 처음에 쓰려던 변이(추격 창을 «당일 포함»으로)는 **쓸 수 없었다.**
> `l[j] ≤ max(a, min(창))` 이 두 창에서 **동치**라 청산 «날짜»가 안 바뀐다(손으로 확인).
> **부수 소득**: 그래서 추격선의 「당일 저가를 쓰면 룩어헤드」 걱정은 **날짜에 관한 한 무해**하다.

## 6. 🚨 헤드라인 표를 읽는 법 — 진입 수가 왜 다른가

두뇌 세션이 보낸 seed 200 표에서:

```
P0 3,019 · H 3,431 · H-noreserve 3,431 · H-avgstop 3,038 · T 3,429 · T-noreserve 3,429
```

**예약 여부는 진입 수를 안 바꾸고(3,431 = 3,431), `add_stop` 은 바꾼다(3,431 vs 3,038).**
원인은 `open_until` 이다 — `floor_entry` 는 손절선을 **올리므로 더 일찍 털리고**,
일찍 털리면 같은 종목의 다음 진입이 **더 빨리 열린다**. 73b 에서 찾은 「필터 위치」와 **같은 기전**이다.

> ### **H 는 「P0 에 피라미딩을 얹은 판」이 아니다. «거래 목록이 다른» 판이다.**
> A·B·C 문턱은 **다른 거래 집합끼리** 비교하고 있다. 결과 문서에 이 줄이 있어야 한다.
> (내 ② 판정의 「`floor_entry` 가 T 의 증액 일정을 20.67% 바꾼다」와 **같은 축의 확장**이다.)
