## 1. ① 결함의 정확한 모양

**`research/handoff/scripts/dataaxis.py` · `_resample` 의 «비순환» 가지:**
```python
while len(out) < n:
    a = rnd.randint(0, max(0, n - block))     # ← 시작점이 [0, n−block] 로 «제한»된다
    out.extend(r[a:a + block])
```

**덮개 수를 세면(자리 `i` 를 덮는 시작점의 개수):**
```
i = 0          →  a = 0 «하나»뿐                     →  **1**
가운데(block−1 ≤ i ≤ n−block)  →  a 가 block 개      →  **block**
i = n−1        →  a = n−block «하나»뿐               →  **1**
```
> ### **비율 = 첫날/가운데 = **1 / block**.  블록 20·40·80 이면 **1/20 · 1/40 · 1/80**.**

**옮겨간 무게**(덜 덮인 몫의 총합) `≈ (block − 1) / n`:
```
block 80 · n≈2,250  →  79/2250 = **3.51%**      (내가 74 판정문에 적은 3.64% 와 맞는다)
block 20 · n≈2,250  →  19/2250 = **0.84%**      (적은 0.85% 와 맞는다)
```
**내가 74-stage9 에 적은 「0.013~0.050배」도 1/80=0.0125 · 1/20=0.05 로 정확히 맞는다.** ✅

### 🚨 그런데 **「36분의 1」은 코드에서 안 나온다**

```
BLOCKS = (20, 40, 80)   →  1/20 · 1/40 · 1/80   —  **36 은 없다**
```
셋의 산술평균(46.7)도, 비율 평균의 역수(34.3)도 36 이 아니다. **재현이 안 된다.**

> ### ★ **이것이 내가 미너비니 감사에서 이름 붙인 «수치가 표류한 인용»이다 — 이번엔 «우리 메모리 안»에서.**
> **구조(「양 끝이 훨씬 덜 뽑힌다」)는 맞고 «숫자»만 미끄러졌다.**
> **그래서 대충 보면 통과한다** — 그게 그 유형이 위험한 이유고, 여기서 그대로 재발했다.
>
> **정정 제안: 「36분의 1」 → 「블록에 따라 1/20 ~ 1/80 (옮겨간 무게 0.84~3.5%)」**

## 3. ③ 고친 판 설계 — 🚨 **고침은 «하나»가 아니라 «둘»이다**

### 3-1. 무엇으로 고치나 — **순환 블록(이미 구현돼 있다)**

`CYCLIC[0] = True` 가 **순환 블록 부트스트랩**(Politis–Romano)이고, **모든 날이 정확히 `block` 번** 덮인다.
표준 방법이고 **새로 짤 것이 없다.** 양 끝만 «보정»하는 것보다 낫다 — 보정은 임의 가중을 낳는다.

### 3-2. 🚨 **그런데 순환만 켜면 «다른 것»이 틀어진다**

내가 77 ②(`74v --stage7`)에서 실측한 것:
```
                     구간 폭        중앙
이동 × 스트림 10     143~156       −2.02 ~ −4.16%      ← 참값 −2.25% 근처
**순환 × 스트림 10   203~215       +4.77 ~ +7.27%**    ← 🚨 폭 1.4배 · **중앙이 부호까지 바뀐다**
순환 × 스트림 200    158~166       −1.73 ~ +2.15%      ← 참값 근처로 «돌아온다»
```
> ### **순환 «단독»은 고침이 아니라 «다른 편향»이다. 스트림 10 과의 상호작용이 본체다.**
> **고침 = 순환 + `N_STREAM` 을 200 으로.** 둘 중 하나만 하면 딴 데가 틀어진다.
> (77 ② 에서 내가 「스트림을 올리는 것이 더 «근본적인» 수정」이라 적은 그대로다.)

### 3-3. 🚨 유형 24′ 관문 — **「고치기 «전»이 실패하는가」**

**합성 계열로 «기지답» 시험을 만든다**(백테스트 불필요 · 몇 초):
```
계열 r 을 만든다:  가운데 n−2 일은 «전부 0» · 첫날과 마지막날만 +X
                  → 참 총수익 = (1+X)² − 1  ← «우리가 아는 답»

이동 블록  양 끝이 1/block 로만 뽑힌다  →  재표집 총수익이 참값보다 **작아야 한다**
순환 블록  모든 날이 block 번           →  재표집 총수익이 참값에 **맞아야 한다**
```
> ### **관문: 「이동 블록 판이 참값을 «벗어나야» 통과」.**
> **안 벗어나면 그 관문은 분해능 0이고, 「고쳤다」의 증거가 못 된다.**
> **그리고 벗어나는 «크기»가 (block−1)/n 예측과 맞는지도 같이 찍는다** — 맞으면 기전까지 확인된다.

★ **이 관문은 자료가 필요 없다.** 지금 «판정 창을 안 쓰고» 만들 수 있고,
**만들어 두면 다음에 재표집을 건드릴 때마다 돈다.**

## 4. ★ 요구하신 것 — **뒤집힌 그 1칸을 «설명»한다**

> 「12칸 중 1칸이 왜 뒤집혔는지 설명 없이 「작다」로 닫지 마십시오」

**먼저 «이상한 점»부터**: 순환은 폭을 **넓힌다**(3-2). 넓어지면 **0 배제가 «어려워»진다.**
**그러니 「순환으로 바꿨더니 0 배제가 «생겼다»」는 폭만으로는 설명이 안 된다.**

**설명은 «중앙»에 있다:**
```
순환 × 스트림 10 은 폭만 넓히는 게 아니라 **중앙을 크게 옮긴다**
   내 실측: 참값 −2.25%  →  순환×10 중앙 **+4.77 ~ +7.27%**  (부호까지 바뀐다)
→ 중앙이 크게 옮겨가면 **넓어진 구간에서도 0 을 배제할 수 있다**
```
> ### **→ 그 1칸의 뒤집힘은 «가장자리 편향이 고쳐져서»가 아니라**
> ### **«순환과 스트림 10 의 상호작용이 중앙을 옮겨서»다.**
> **즉 그 뒤집힘은 «수정의 효과»가 아니라 «불완전한 수정의 부작용»이다.**
> 그리고 **3-2 의 처방(스트림 200)을 같이 걸면 사라질 것으로 예상된다** — 순환×200 은 참값 근처다.

⚠️ **이건 «설명 후보»이지 확인이 아니다.** 확인하는 법:
> **74 의 그 12칸을 «순환 × 스트림 200» 으로 한 번 돌린다.**
> **뒤집힘이 사라지면 설명이 맞고, 남으면 다른 원인이 있다.**
> **A급 재실행에 그 12칸을 얹으면 «따로 돌릴 필요가 없다».**

```
② A급 셋에서 판정이 «안 바뀔» 것     →  **충족** (77·75 둘 다 미통과 유지)
원본 캐시 md5                        →  세 실행 모두 **6/6 그대로**
```

### 🚨 그런데 — **43·47·48·59·60·61 은 «순환 × 10» 으로 돌렸다**

내가 74v 때 돌린 116칸은 **`N_STREAM` 기본값 10** 이었다. **오늘 확정한 고침은 «순환 + 200» 인데,
그 여섯은 절반만 적용된 판이다.**

**방향이 «한쪽»이 아니다:**
```
순환×10 → 순환×200   폭이 **좁아진다**(203~215 → 158~166, 약 23%)  →  0 배제가 «쉬워진다»
                     중앙이 참값 쪽으로 **돌아온다**(+4.77~+7.27 → −1.73~+2.15)
```
> ### **좁아지는 것과 중앙이 옮겨오는 것이 «반대로» 작용하므로, 어느 쪽인지 «모른다».**
> **내 stage9 판정문에 「이 판은 「뒤집힘 없음」쪽으로 보수적이다 · 200 스트림으로 다시 돌리면
> 뒤집히는 칸이 생길 여지는 남는다 — 안 쟀다」고 «적어 뒀는데», 그 여지가 아직 그대로다.**

**그리고 이번에 74 에서 실제로 «×10 에서 뒤집힌 칸이 ×200 에서 사라진» 사례가 나왔다** —
**반대 방향(×10 에서 안 뒤집힌 칸이 ×200 에서 뒤집히는 것)도 가능하다는 뜻이다.**

> **권함: 여섯을 «순환 × 200» 으로 한 번 더. 그때까지는 「닫혔다」가 아니라
> **「A·B급은 닫혔고 여섯은 절반만 적용됐다」**로 적어야 한다.**
> (내 실행 기준으로 세 판이 각 20~40분이었으니 여섯은 한 번에 돌릴 만하다.)
