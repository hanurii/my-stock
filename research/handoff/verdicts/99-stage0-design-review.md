## 1. 원전 산수 — **검산했다. 완전히 닫힌다**

계좌 $40,000 으로 역산:
```
¼   6.25% × 40,000 = $2,500  · 손절 $250   → **−10.0%** · 계좌 위험 **0.625%**
½  12.50% × 40,000 = $5,000  · 손절 $500   → **−10.0%** · 계좌 위험 **1.25%**
전체 25.0% × 40,000 = $10,000 · 손절 $1,000 → **−10.0%** · 계좌 위험 **2.50%**
```
> ### **세 칸 «전부» 손절 −10% 다. 그리고 「평균 1.25 / 최대 2.5」가 «사다리의 두 칸»이라는 정정이 맞다.**
> **밑칸 0.625% 까지 세 칸이 정확히 2배씩**이다. 「두 배씩 늘린다」와 일치한다.

★ **그리고 이것이 내가 3차에서 「숫자들이 한 곡선 위에 있다」고 한 것을 «완성»한다** —
곡선이 아니라 **«세 점»이었고, 세 점이 한 사다리였다.** 웹의 흩어진 값들은 그 세 점의 그림자다.

### 🚨 그런데 — **본문이 «트윗»과 충돌한다. 이건 새로 나온 것이다**

```
트윗 [검색요약]  "A 25% position size **requires a 5% stop**"   →  25% × 5%  = 위험 **1.25%**
본문 [1차·사용자 전사]  25% 포지션 · 손절 $1,000                →  25% × 10% = 위험 **2.50%**
```
> ### **같은 25% 포지션에 손절이 «5%» 와 «10%» 로 갈린다. 둘 다 그의 것이라고 한다.**

**세 갈래 중 하나다:** ㉠ 트윗이 다른 맥락(더 보수적인 계좌 위험) · ㉡ 트윗 전달이 부정확
(내가 「미확인 전달」로 분류한 그것) · ㉢ 본문 표가 «예시»이고 트윗이 «규칙»

🚨 **그리고 이게 ㉣(손절을 −10% 로 바꿈)에 직접 걸린다.**
**99 는 −10% 를 골랐는데, 트윗이 맞으면 전체 포지션의 손절은 −5% 여야 한다.**
→ **「본문 표를 따랐고, 트윗과 어긋난다는 것을 안다」를 사전등록에 «적으시라».**
   지금은 골랐다는 사실만 있고 **충돌을 인지했다는 기록이 없다.**
→ **그리고 이건 「책이 필요한 목록」의 «새 항목»이다** — 둘 중 어느 것이 규칙인가.

## 2. ㉠ 사다리 — **5건 창은 «상태»와 다르다. 반례가 있다**

```python
def ladder(recent):        # 항상 lvl=0 에서 «다시» 시작한다
    lvl = 0
    for w in recent: lvl = min(2, lvl+1) if w else max(0, lvl-1)
```
**연속 `W L W L W` 를 넣어 보면:**
```
참 상태 0 에서 →  1,0,1,0,1  →  **lvl 1 (½)**
참 상태 1 에서 →  2,1,2,1,2  →  **lvl 2 (전체)**
참 상태 2 에서 →  2,1,2,1,2  →  **lvl 2 (전체)**
```
> ### **같은 5건인데 «시작점»에 따라 답이 갈린다. 5건 창은 상태를 복원하지 못한다.**
> **방향: 항상 0 에서 시작하므로 «참 상태 이하»로만 나온다 = 사다리를 «낮게» 잡는다(보수적).**

**고침이 한 글자다: `recent` 를 «5건」이 아니라 «전체»(또는 20건)로.**
걸음이 [0,2] 에 갇혀 있어 **20건이면 시작점을 사실상 잊는다.** 상태 변수를 따로 들 필요 없다.
⚠️ **그리고 두 판(5 vs 전체)이 «얼마나 다른지» 한 번 찍으시라** — 안 다르면 그대로 두면 되고,
다르면 **지금 판은 사다리를 낮게 잡은 것**이다.

### 🚨 그리고 더 큰 것 — **「한 칸 내림」은 본문에 «없다»**

```
본문   「성공 거래의 «연속선상»에서 두 배씩 늘린다」      ← «올리는» 규칙만 명시
본문   「손실 나는 종목은 «매도»해 비중을 줄인다」        ← 이건 «보유 관리»다
코드   실패하면 다음 거래의 «크기»를 한 칸 내린다        ← **본문에 없다**
```
> **「손실 종목을 판다」와 「다음 거래를 작게 산다」는 다른 행동이다.**
> 정본에는 내리는 사다리가 있지만(크기 축소 → 설정 조이기 → …), **이 발췌에는 없다.**
> → **「한 칸 내림」을 «본문 밖 — 정본/우리 구성»으로 라벨하시라.**
> ⚠️ 그리고 **대안 읽기가 실제로 다르다**: 내리는 규칙이 없으면 사다리가 **«한 방향 래칫»**이 되고,
> 그건 완전히 다른 전략이다. **어느 쪽인지가 결과를 가른다.**

## 3. ㉡ `slots=12` — **문다. 그리고 하필 «사다리가 만드는 행동»을 자른다**

> 사다리 쪽이 12(상한)에 붙고 대조는 7~8

**기전이 뻔하다: 사다리는 ¼(6.25%)로 시작하므로 «같은 자본으로 4배 많은 종목»을 들 수 있다.**
→ **12 로 막는 것은 사다리의 «정의»를 자르는 것**이다.

🚨 **그리고 이건 내가 86 에서 찾은 것과 «같은 자리»다:**
> 「3칸에서는 `cap 33.3%` 가 아니라 «위험규칙 25%» 가 먼저 문다 —
>  격자가 «자기 사양»대로 안 돈다」

**한 팔에서만 제약이 무는 비교는 「사다리 vs 대조」가 아니라 「막힌 것 vs 안 막힌 것」이다.**

> **처방:** 상한을 **안 물 때까지 올리거나**(원전 본문에 개수 상한이 «없다»는 관찰이 맞다),
> 최소한 **두 팔의 «동시보유 분포와 평균 노출»을 결과에 찍으시라.**
> 상한에 붙은 채로 낸 수는 **「사다리가 이만큼 든다」가 아니라 「우리가 이만큼만 허락했다」**이다.

## 4. ㉢ B★(수익÷낙폭) — **너무 유리하다. 그런데 고치는 법이 있다**

**이유는 정확하다**(사다리는 노출을 낮추므로 자산으로만 재면 정의상 진다).
🚨 **그런데 MAR 은 «덜 드는 것»을 «그 자체로» 보상한다.**
```
노출을 반으로 줄이면  수익도 낙폭도 준다  →  MAR 은 «아무 기술 없이도» 오를 수 있다
```
**즉 B★ 는 「사다리가 좋은가」가 아니라 「덜 들면 MAR 이 오르나」를 잴 위험이 있다.**

> ### **처방 — 86 에서 배운 그대로: «무작위 사다리» 대조를 넣으시라.**
> ```
> 가짜 사다리 = 최근 성적과 «무관하게» ¼ / ½ / 전체 를 «같은 비율»로 뽑는다
>              (진짜 사다리가 낸 비율을 그대로 맞춘다)
> → 형태(노출이 오르내린다)는 같고 «내용»(성적에 반응한다)만 없다
> ```
> **가짜 사다리도 MAR 이 같이 오르면, B★ 가 잰 것은 «덜 드는 것»이지 «사다리»가 아니다.**
> 86 ㉱ 에서 정확히 이 대조가 「규칙을 쓴 것이지 그 규칙이 아니다」를 갈랐다.

**그리고 최소한 «평균 노출»을 두 팔 다 찍으시라** — 안 찍으면 B★ 를 읽을 수가 없다.
*(A★ 「이기는 판 >55%」는 짝비교 승률이라 **seed 축**이다. 세 창 모두 요구하는 것이 자료 축 보호이니 그건 맞다.)*

## 5. ㉣ 손절 −10% — **두 팔은 문제없다. 문제는 «바깥»이다**

코드를 봤다: `ev8` 은 **관문 ②(항등 확인) 전용**이고, 본 비교는 **두 팔 다 `ev10`** 이다. ✅
**같은 진입 집합 위에서 비교하므로 ㉣ 자체는 깨끗하다.**

🚨 **그런데 «과제 사이» 비교가 깨진다:**
```
74 · 82 · 86 · 91 · 94   손절 **−8%**
99                        손절 **−10%**   →  진입 8,808 vs 9,172 (−364)
```
**12ii 가 「진입 수를 지배하는 건 손절폭」이라 했으므로 진입 집합이 «다르다».**
→ **99 의 자산·MAR 을 74·91 의 것과 «나란히 놓지 마시라».** ext 때와 «같은 규약 문제»다.
**결과 문서에 「−10% 판이라 −8% 판과 직접 비교 불가」를 박으시라.**

## 6. ㉤ 켈리 — **분리한 것이 맞다**

켈리는 **«유도»이지 그가 문턱으로 제시한 규칙이 아니다.** 문턱에 걸면 새 축이 되고 예산을 쓴다.
**서술로 두면 예산 0** — 3절에서 내가 정한 「서술 / 검정」 선 그대로다. ✅
⚠️ **다만 라벨은 붙이시라** — 「등록 밖 · 서술 · 판정에 안 씀」.

## 7. `cash_rule` 결함 — **새 유형이라기보다 «재발»이다**

```
증상   slots=16 이면 per_slot 이 현금을 16 으로 나눠 «자동으로» 6.25% → 원전의 25% 가 안 나옴
검출   **체결 수가 양쪽 «똑같이» 나왔다**
```
🚨 **86 에서 내가 찾은 것과 같은 형태다** — 「제약이 둘인데 «어느 것이 무는지»를 안 보고 격자를 돌렸다」.
거기서는 `cap 1/칸` 과 `위험규칙` 이었고, 여기서는 `cap` 과 `cash_rule` 이다.

> ### **새 유형보다 «86 의 발견을 강화»하는 편이 낫다:**
> **「크기를 정하는 제약이 둘 이상이면, 각 칸에서 «어느 것이 무는지»를 표로 찍는다.」**
> (86 에서 실제로 그 표를 만들어 3칸의 사양 위반을 찾았다.)

★ **그리고 «검출기»는 따로 적을 값어치가 있다:**
> **「처리와 대조에서 «달라야 할» 값이 «같으면» 처리가 안 걸린 것이다.」**
> 유형 24(양성 대조)의 사촌인데, **부수 지표(체결 수)로 본다**는 점이 새롭다.
> **체결 수·동시보유·노출은 공짜로 나오니 «항상 나란히 찍으면» 이런 결함이 스스로 드러난다.**
