# 56번 — **5회차: SEPA ②펀더멘털 · ③촉매** (사전등록, 2026-08-25)

> 38번 §6 의 5회차를 «구체화»한다. **값을 보기 전에 적는다.**

## 1. 무엇을 붙이나 — **미너비니 판이지 오닐 판이 아니다**

🚨 **CANSLIM 은 오닐 것이다. 미너비니는 SEPA 다.** 둘은 «붙이는 방식»이 다르다.

| | 미너비니 | 오닐 |
|---|---|---|
| 순서 | **기술적 구조가 먼저**, 펀더멘털은 **확인** | 펀더멘털로 **먼저 거른다** |
| 이 과제 | **방아쇠 26,508 을 그대로 두고 관문만 덧붙인다** | 유니버스를 줄인다 — **다른 과제** |

**사용자는 SEPA 로만 고르고 펀더멘털은 거의 안 본다**(본인 확답 26-08-25).
→ 이 회차는 **「원전에 있는데 안 하던 걸 붙이면 나아지나」** 다. **1회차와 같은 구조**이고 그게 제일 크게 이겼다.

## 2. 🚨 관문은 **둘만** 만든다 — 칸을 늘리면 답이 아니라 «고른 것»이 된다

23번에서 배웠다: **효과가 전혀 없어도 12칸 중 최선을 고르면 +87.47%p 가 나온다.**
그래서 **사전에 둘로 고정하고, 나중에 늘리지 않는다.**

| | 이름 | 정의 |
|---|---|---|
| **G1** | **느슨** | 최근 분기 **EPS YoY ≥ +20%** 이고 **매출 YoY ≥ +20%** |
| **G2** | **Code 33** | **EPS YoY ≥ +33%** 이고 **매출 YoY ≥ +33%** 이고 **순이익률 확대** |

> **가속(직전 분기보다 성장률이 높은가)은 «세 번째 칸»이 되므로 넣지 않는다.**
> 넣고 싶으면 이 과제가 끝난 «뒤에» 별도 사전등록으로 한다.

## 3. 자료 — **SEC EDGAR `frames`, 요청 ~70회**

종목별 `companyfacts` 는 **3,023 회** 요청이라 과하다. `frames` 는 **한 분기 전 종목**을 한 번에 준다.

```
https://data.sec.gov/api/xbrl/frames/us-gaap/<개념>/<단위>/CY<연><분기>.json
개념: EarningsPerShareDiluted · Revenues(+RevenueFromContractWithCustomer...) · NetIncomeLoss
분기: 2020Q1 ~ 2026Q2  →  약 26분기 × 3개념 ≈ **78 요청**
```

- **User-Agent**: 사용자가 지정 — `han95210@naver.com` (26-08-25 명시 허가)
- **속도**: SEC 한도는 10/초지만 **오늘 3요청에 403 을 맞았다** → **1 요청/2초**로 간다
- **저장**: `.cache/edgar/` (gitignore 됨). ⚠️ **디스크 여유 8.1GB (97% 사용)** — 필요한 필드만 남긴다

### 🚨 시점 처리 — `frames` 에는 «제출일»이 없다
**보수적 고정 지연을 쓴다: 분기 종료 + 60일 이후부터 그 분기 수치를 쓴다.**
실제 제출은 대개 40~45일이므로 **이 가정은 언제나 «실제보다 늦다» — 이르지 않다.**
**룩어헤드가 생길 수 없는 방향이다.** (정확한 제출일이 필요하면 나중에 `companyfacts` 로 올린다.)

## 4. 관문 (실패하면 멈춘다)

1. **티커 → CIK 매칭률.** 3,023 중 몇 개가 붙는가. **60% 미만이면 멈춘다.**
2. 🚨 **매칭 실패를 「탈락」으로 처리하지 않는다.** 그러면 «자료 유무»가 관문이 되어
   외국기업·ADR·상폐주가 통째로 한쪽에 몰린다. **제3군으로 따로 센다.**
3. **G1 통과율이 5% 미만이거나 95% 초과면 멈춘다** — 관문이 아니라 상수다.
4. **탈락군의 표본이 500건 미만이면 멈춘다** — 비교 대상이 없다.

## 5. 사전등록 문턱 — **넘으려면 무엇이 얼마여야 하는지 같은 줄에**

**모집단은 «진입 집합»으로 고정한다**(00-summary-table §세 모집단). 라벨 없이 쓰지 않는다.

| | 문턱 | 넘으려면 |
|---|---|---|
| **A** | 통과군 − 탈락군 **거래당** 95% 구간이 **0 배제** | \|차이\| > MDE. **MDE 를 «먼저» 내고 적는다** |
| **B** | 자산 축(슬롯5 짝비교) | 38번에서 이미 계산됨 — **관문은 체결을 줄이므로 필요치가 오히려 오른다.** **판정 못 냄이 예정** → **정보 항목** |
| **C** | 연도별 부호 | A 통과 시, **한 해를 빼면 뒤집히는가**(23번 유형). 뒤집히면 강등 |
| **D** | 상위 꼬리 | A 통과 시, **상위 1·5·10건 빼고 재계산**(유형 19). 사라지면 강등 |

> **B 는 「달성 불가한 문턱」이라 판정에서 뺀다** — 54번 D 와 같은 처리.
> **A 가 주판정.** 예상 MDE 는 16번(3,776건에서 0.95%p) 기준 **9,138건이면 0.6%p 근처**.
> **관측된 선별 효과가 0.4%p 자릿수였으므로 «아슬아슬하다» — 이걸 미리 적어 둔다.**

## 6. 미리 적는 한계

1. **16번에서 검출기(VCP·3C·PP)는 판정 불가였다**(−0.44%p). 펀더멘털도 추세 위에 얹는
   **또 하나의 선별층**이라 **같은 자릿수로 나올 수 있다.** 그래도 하는 이유는
   **표본이 63건이 아니라 9,138건**이고 **통과하면 `/sepa` 에 관문이 붙는다**(할 일이 명확).
2. **미국 개발 구간이다.** 표본 밖(2017-09~2021-01)은 **열지 않는다** — 한 번뿐이다.
3. **한국 이식은 이 과제에 없다.** DART 분기 캐시가 소실 상태다.
4. `Revenues` 는 개념이 회사마다 다르다(`RevenueFromContractWithCustomerExcludingAssessedTax` 등).
   **대체 개념 목록을 코드에 적고, 어느 개념으로 붙었는지 세어 남긴다.**
