## 0. 왜 이것을 «먼저» 하는가

사용자 지시는 **「실적 자료로 수익률을 더 끌어올리자」**였다. 그 전에 이것이 먼저다.

> ### **★ 우리 규칙이 표본 밖에서 안 서면, 그 위에 얹는 실적 축은 «전부» 무의미하다.**

그리고 사용자 표현 **「무조건 더 나은 방법을 찾을 때까지 멈추지 말자」**에 대한 답이기도 하다.
**계속 뒤지면 «찾아지지만» 가짜일 확률이 같이 오른다**(한국 88·89에서 실제로 겪었다).
**정공법은 「더 많이 뒤지기」가 아니라 「더 긴 자료로 재기」**이고, 이 창이 정확히 그것이다.

## 확인된 것 둘 (안 고침)

**① D★ 의 seed 짝맞춤이 «생각보다 강하다».** 근거가 seed 번호가 아니었다:
```python
# slot_sim.py:55
def order_key(seed, t):
    return random.Random("%d|%s|%s|%s" % (seed, t["code"], t["scan_date"], t["pattern"])).random()
```
난수 키가 **(seed, 거래 신원)**에 걸려 있어 같은 seed 면 **같은 거래가 어느 사다리에 있든 같은 키**를 받고,
`lvl2 ⊆ lvl1 ⊆ by0` 로 포개져 있어 **공유 거래의 상대 순서가 유지된다.**
> **세 칸이 나눠 갖는 것은 「seed 번호」가 아니라 «추첨 그 자체»다. 짝비교의 가장 강한 형태다.**

**② `boot_ci` 는 정통 중앙값 부트스트랩이 맞다.** (n 복원추출 → 중앙값 → 4,000회 → 2.5/97.5, 난수 고정)
부수: 세 칸의 `yrs` 가 같아 `cagr` 는 총수익의 **단조변환**이다 → **`equity_pct` 로 순서를 세는 것과
「연환산」으로 세는 것이 정확히 같다.** 사전등록 문구와 안 어긋난다.

## 개정 2-㉠ — **E 의 MDE 가 «평균»의 표준오차를 쓰고 있었다 (20% 낙관)**

`2.8`(=1.96+0.84)은 맞다. 틀린 건 `sd/√n` 이 **평균**의 SE 인데 비교 대상 `bmed` 은 **중앙값**에서
나온다는 것이다. 정규 근사에서 **중앙값의 SE 는 1.253배** 크다.
```
바뀜:  SE ← (boot_ci 의 hi − lo) / 3.92        ← 정규 가정도 필요 없다
      MDE = 2.8 × SE
옛 식(2.8·sd/√n)도 «함께 찍되» 「20% 낙관이라 안 쓴다」고 적는다.
```

## 개정 2-㉡ — **C★ 의 MAR 이 「두 중앙값의 비」다** (유형 3 사촌)

`중앙자산 ÷ 중앙MDD` 는 **비의 중앙값이 아니다.** 벤치마크는 경로가 하나라 정확하므로 **자가 한쪽만 흔들린다.**
→ **등록 통계는 그대로 둔다**(81 의 14.42 와 이어져야 한다). **라벨을 붙이고**
   판 «각각»의 비를 중앙낸 `median(|eq_s / mdd_s|)` 를 **옆에 참고로** 찍는다.

## 개정 2-㉢ — **A★ 의 연수가 두 쪽에서 다르게 계산된다**

```
전략     yrs = (d1 − d0)/365.25          ← 창의 «경계»
벤치마크 yrs = (ds[-1] − ds[0])/365.25    ← 자료가 «있는» 날
```
지금은 며칠 차지만 **덮개가 짧으면 조용히 어긋난다**(1999 창에 계열이 2000부터면 1년).
→ **`assert abs(Δyrs) < 0.05`.** 요점은 크기가 아니라 **「괜찮을 것」이 검사되고 있지 않았다**는 것.

`lvl1` 은 섹터 라벨이 없으면 **그냥 통과**시킨다. §6-1 은 라벨의 «정확도»만 적었고 «덮개율»은 없었다.

# 개정 3 — **가짜약을 「등록된 미결」로 남긴다** (돌리지 «않고» 설계만 확정)

## 왜 안 돌리는가 — **M37-5 「성공하면 사용자가 뭘 다르게 하나」**

**사실 확인**: 등급 밴드 `[0.10, 0.30)` 는 **실거래에 없다. 조사 전용이다.**
```
확인 방법  strategy_params.py · scripts/*.py · src/lib/*.ts · .claude/skills/**
           을 `백분위|percentile|0\.10|0\.30|in_pct` 로 훑음 → 실거래 경로 **0건**
실거래     주도 섹터 ①~⑨ = 사용자가 «직접 고른» 목록이고 **배지**다(필터 아님)
```
> **가짜약이 어느 쪽으로 나와도 사용자가 내일 다르게 할 일이 없다.**
> → **「못 가린다」로 두고 넘어간다.** 🚨 **「안 해봤다」와 다르다** — 설계는 아래에 확정해 둔다.

## 확정 설계 — **나중에 돌릴 때 이대로 쓴다. 그때 다시 고민하지 않는다**

### 뜻 없는 기준 = **「섹터-달 «안»에서 등급값을 섞는다」**

② 의 정의를 뜯으면:
```

내용 = 「그 순위가 «6개월 수익률»이다」   ← 이것만 없앤다
```
| | `sec_top`(①) | 섹터-달 통과 개수 | 밴드 | 달마다 회전 |
|---|---|---|---|---|
| 이 설계 | **원래 값 그대로** | **동일** | 동일 | **된다** |

**형태가 완벽히 맞고 내용만 사라진다.** ①→② 증분이 격리된다.

### ⛔ 기각된 두 후보 — **이유가 서로 다르다**
```
티커 해시     구성원이 «고정»된다. ② 는 달마다 바뀐다.
              🚨 88번에서 **내가 스스로 한계로 적은 바로 그 자리**다
scan_date 해시  «뜻 없지» 않다. 날짜로 고르면 **국면이 통째로 들고난다**
                (2008 남기고 2009 버리는 식) → 대조가 아니라 **새 실험**이 된다
```

### 도구 — **`61b:make_flags(shuffle_rnd=)` 가 이미 그 물건이다**
🚨 다만 지금은 **«달 전체»에서 섞어 `sec_top` 까지 무너뜨린다** → ①→② 증분을 격리 못 한다.
`sec_top` 을 «원래 값으로 확정한 뒤» 섹터 안에서만 섞도록 세 줄을 옮기면 된다.
🚨 **`61b` 를 «고치지 않는다»** — 43·47·48·61 이 쓴다. **91 쪽에 변형을 따로 두고 그 사실을 적는다.**

### 판수 — **K ≥ 178. 20 은 «원리적으로» 못 넘는다**
```
순열 p 바닥 = 1/(K+1)
K=20  → 0.048        이 창에서 이미 본 칸 9 → 본페로니 0.05/9 = 0.0056
0.0056 을 넘으려면  1/(K+1) ≤ 0.0056  →  **K ≥ 178**   → **K = 200 고정**
```
계산이 벅차면 **seed 를 줄이고 K 를 지킨다.** 판정을 정하는 것은 K 다.
(K=200 × seed 50 이면 승률이 거칠어지니 **거칠어졌다고 적는다.**)
