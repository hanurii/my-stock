## 고친 것 둘

### 1. 난수 어긋남 — 규칙이 바뀌면 "같은 seed"가 같은 순서를 뜻하지 않았다

옛 코드는 `rnd.shuffle(c)`를 **"빈 슬롯이 있고 그날 후보가 있을 때만"** 호출한다.
청산 규칙이 바뀌면 → 결착일이 바뀌고 → 빈 슬롯 패턴이 바뀌고 → **셔플 호출 횟수가 달라진다.**
난수 스트림이 어긋나 두 규칙이 **다른 후보 순서**를 본다. 짝비교의 전제가 깨져 있었다.

**고침:** 날짜별 후보 순서를 **시뮬 경로와 무관하게** 뽑는다.

```python
# 날마다 독립된 난수 — 빈 슬롯 유무와 무관하게 항상 같은 순서가 나온다
rnd_d = random.Random("%d|%s" % (seed, d))   # d = 그날 날짜 문자열
c = byday[d][:]
rnd_d.shuffle(c)
```

> **[2026-08-23 정정]** 최초 사양에 적은 `random.Random((seed, d))`는 **파이썬 3.12에서 동작하지 않는다**
> (튜플 seed 미지원, TypeError). 위처럼 **문자열 seed**로 쓴다 — 문자열 seed는 재현 가능하고,
> "날마다 독립 · 시뮬 경로와 무관"이라는 성질은 그대로다. 조사 세션이 잡아낸 사항이다.

이러면 모든 규칙·모든 칸이 **매일 같은 후보 순서**를 본다.
정렬 규칙(거래대금 순 등)을 검정할 때도 이 셔플 뒤에 정렬을 얹어 동점만 무작위가 되게 한다.

### 1-1. 목록을 섞지 말고 **거래마다 정렬키**를 뽑는다 [2026-08-23 보강]

> 위 방식에는 구멍이 하나 남는다(검증 세션 실측). **그날 후보 목록 전체를 섞기 때문에
> 목록에서 1건만 빠져도 남은 공통 종목의 상대 순서가 달라진다.**
> 12번 **(i) 고정 진입 판은 안전하지만 (ii) 자체 진입 판은 여전히 짝이 아니다**
> (칸마다 후보 목록의 구성원이 다르다). 03·09처럼 후보 구성이 달라지는 검정도 마찬가지다.

**고침 — 이쪽을 정본으로 한다:**

```python
def order_key(seed, e):
    return random.Random("%d|%s|%s|%s" % (seed, e["code"], e["scan_date"], e["pattern"])).random()

c = sorted(byday[d], key=lambda e: order_key(seed, e))
```

거래마다 **자기 고유의 난수 키**를 갖게 되므로, 후보가 1건 빠져도 남은 거래의 상대 순서가
그대로 유지된다(검증 세션 실측 True). 날짜별 셔플은 이것으로 대체한다.

### 2. 같은 날 결착 → 같은 날 재진입

옛 코드는 결착 처리 직후 그 슬롯을 같은 날 다시 채운다. **빨리 결착하는 규칙일수록 이득**이라
좁은 손절·낮은 목표에 유리한 방향의 편향이다(M1의 ambiguous 편향과 같은 방향).

**고침:** 결착한 슬롯은 **다음 거래일부터** 재사용한다.

### 2-1. 손익은 언제 자본에 반영하는가 — **결착일에 반영한다** [2026-08-23 확정]

최초 사양이 슬롯 해제만 정하고 손익 반영 시점을 안 정해 두 해석이 가능했다.
옛 코드는 셋(결착 · 현금 반영 · 슬롯 해제)이 한 덩어리로 붙어 있었다.

**결정: 손익도 슬롯도 다음 거래일에 반영한다 (④안).**

> **[2026-08-23 번복 — 두뇌 세션의 최초 판단이 틀렸다]**
> 처음엔 "손익은 결착일에 반영"(⑤안)으로 정했다. 근거는 "+20%에 팔았으면 그날 내 돈"이었다.
> **검증 세션의 반박이 옳다:** 이 하네스는 **진입이 그날 시가**이고 **결착 손익은 그날 종가**다.
> ⑤안은 **오후에 확정되는 돈으로 그날 아침 매수 크기를 정한다** — 슬롯이 아니라 **자본 쪽에
> 남은 같은 종류의 룩어헤드**다. 한국 결제가 T+2인 것도 같은 방향이다.
> 실측으로도 ⑤가 ④를 우세율 89.5%·+1.2%p로 이기는데, 이는 **빨리 결착하는 규칙일수록 유리한**
> 방향이라 M1·A4와 같은 계열의 잔여 편향이다.
>
> ④는 "D일 종가에 확정된 돈으로 D+1일 아침에 산다"로 자본과 슬롯이 **한 시점에서 일관**된다.

**최종 후보로 올라온 칸은 ④·⑤ 두 해석 모두에서 현행을 이겨야 한다**(전 24칸에 다 돌릴 필요는 없다).
④가 정본이고 ⑤는 민감도다.

## 그대로 두는 것

- 자본 1.0에서 시작, 진입 시 **`eq / slots`** 배분(현재 자본의 1/5)
- 슬롯 5개, 초과 후보는 그날 버림(다음 날로 넘기지 않음)
- 순수익 환산 `((1+g/100)*(1-0.0034)/(1+0.0014)-1)*100`
- 수준 추정 = 200회 중앙값(5~95% 병기), 두 규칙 비교 = **같은 seed 400회 짝비교**

## 반드시 함께 내는 것 (개정 v2 M4)

슬롯5 1회가 실제 체결하는 거래는 5.6년 전체에서 **약 466건**뿐이다(3,681건이 아니다).
- **규칙별 평균 체결 건수**를 모든 결과 표에 싣는다.
- **구간별 평균 체결 건수가 30건 미만이면** 그 구간은 "부호 일치" 계산에서 **판정불가**로 뺀다.

## 검증 관문 — 새 정본을 처음 돌릴 때

현행 +20/−10을 새 정본으로 돌려 **옛 값(자산곡선 −20.7%, 최대낙폭 −57.6%)과 얼마나
어긋나는지 먼저 보고**한다.

- **어긋나는 것이 정상이다.** 위 두 결함을 고쳤으므로 같은 값이 나오면 오히려 이상하다.
- **판단은 수준의 밴드가 아니라 짝비교 분포로 한다** [2026-08-23 확정].
  검증 세션 실측: 난수 고침만 떼어 보면 **우세율 50.5% · 차이 중앙 +0.2%p = 사실상 무효과**다
  (중앙값 두 개를 뺀 "−1.6%p"는 표집 잡음이었다). 난수 고침은 원래 **한 규칙의 수준을 바꾸는
  장치가 아니라 두 규칙이 같은 순서를 보게 하는 장치**이므로 이게 맞는 결과다.
- **이 두 고침은 L5(우세율 ≥75%) 문턱의 적용 대상이 아니다.**
  실측으로 재진입 고침은 71.5%, 정본 vs 옛은 63.5%로 75%에 못 미친다. 그래도 고침은 유지한다 —
  **L5는 "새 규칙을 채택할 때"의 문턱이지 "잘못된 동작을 바로잡을 때"의 문턱이 아니다.**
  옛 동작(같은 날 결착한 걸 알고 그날 다시 사기)은 성적과 무관하게 룩어헤드다.
- 어긋난 크기와 방향, 그리고 어느 고침(난수 / 같은날 재진입) 때문인지
  **하나씩 켜고 끈 네 가지 조합**으로 분해해 표로 낸다.
- 이후 **옛 표의 아홉 줄(+30/−7 = +96.9% 포함)은 인용하지 않는다.** 전부 새 정본으로 다시 계산한다.
