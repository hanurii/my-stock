# 01 — 매수 후 일별 경로 자료 만들기 (토대)

**이 지시서는 02~12번 전부의 입력이다. 여기서 합격하지 못하면 나머지를 시작하지 않는다.**

## 왜 필요한가

`bt_*.json`의 이벤트에는 결과(win/loss)·보유일수·최고상승·최대낙폭만 있고
**하루하루 어떻게 움직였는지가 없다.** 그런데 앞으로 검증할 것들이 전부 경로를 요구한다:
첫날 종가(05), 20일선 이탈·시간컷·추적손절(06), N일차 생존(07), +8% 통과 시점(08),
그리고 청산 격자 24칸(12).

경로 자료를 한 번 만들어 두면 **하네스를 다시 안 돌려도** 이 전부를 계산할 수 있다.
(하네스는 8.5GB·수 시간짜리라 24칸을 다 돌리는 건 현실적으로 불가능하다.)

## 입력

- `.cache/bt5y/bt_2021.json` ~ `bt_2026.json` — 이벤트
- `.cache/pdata/price_YYYYMMDD.json` — 원본 일봉 2020-01-02~
- `scripts/canslim_lib/pdata_series.py`의 `build_series` — 등락률 연쇄 수정주가
- `scripts/backtest_volatility_pilot.py`의 `_iter_pdata`, `series_load_end` (그대로 import 하거나 복사)

## 계산 단계

1. 여섯 개 연도 파일에서 `events`를 모아 `result`가 `win`/`loss`인 것만 남기고,
   `(scan_date, code, pattern)` 기준 중복 제거. **건수를 적는다(3,681이어야 한다).**
2. pdata를 `2020-01-02 ~ 2026-08-21 + 300일`(결착 여유) 범위로 흘려 수정주가 시계열을 만든다.
   메모리를 아끼려면 만든 뒤 **이벤트에 등장하는 종목만** 남기고 나머지를 버린다.
3. 이벤트마다 `entry_date`의 인덱스를 찾아, 그날부터 **최대 300거래일** 또는 시계열 끝까지
   `dates / opens / highs / lows / closes`를 잘라 낸다.
4. 매수가 대비 백분율도 함께 적는다: `(값 / entry_price - 1) * 100`.
5. 20일 이동평균도 같이 넣는다(06번의 "20일선 이탈"에 필요). 매수일 이전 19일을 포함해 계산하되
   **경로 배열에는 매수일부터**의 값만 싣는다.

## 출력

`.cache/bt5y/out/paths.json` (또는 크면 연도별 분할 `paths_2021.json`…):

```json
{
  "built_at": "...",
  "n_events": 3681,
  "paths": [
    {"code":"007110","scan_date":"2025-01-02","entry_date":"2025-01-03","pattern":"VCP",
     "entry_price":2254.85,
     "dates":["2025-01-03", "..."],
     "o":[...], "h":[...], "l":[...], "c":[...],
     "ma20":[...],
     "o_pct":[...], "h_pct":[...], "l_pct":[...], "c_pct":[...]}
  ]
}
```

## ★ 합격 관문 (이걸 통과해야 다음으로 간다)

경로 자료만으로 **+20% / −10% 선착**을 다시 계산해
원본 이벤트와 아래 셋이 **3,681건 전부 일치**하는지 확인한다:

| 항목 | 일치 건수 | 불일치 건수 |
|---|---|---|
| `result` (win/loss) | | |
| `days_held` | | |
| `gain_at_resolve_pct` (소수 둘째 자리) | | |

- 판정 규칙은 `scripts/canslim_lib/pivot_backtest.py`의 `simulate_pivot_trade`와 **똑같이** 한다.
  특히 **매수일 당일에 목표·손절을 둘 다 건드리면 `ambiguous`**, 매수일 당일 손절만 건드려도
  `ambiguous`이다(그래서 확정 표본에서 이미 빠져 있다).
- 목표·손절 기준선은 **피벗이 아니라 `entry_price`** 다(하네스가 `simulate_pivot_trade`에
  `epx`를 넘긴다 — 인자 이름이 `pivot`이라 헷갈리기 쉽다).
- **불일치가 1건이라도 나오면 원인을 먼저 규명하고 보고한다.** 원인을 못 밝히면
  02~12번은 경로 자료 대신 하네스 재실행으로 가야 하므로, 그 사실을 크게 적는다.

## `results/01-path-build.md`에 실을 것

- 이벤트 건수(확정 / ambiguous / unresolved)
- 시계열을 못 만든 종목이 있으면 종목코드와 사유
- 위 합격 관문 표
- 경로 길이 분포(중앙·최대), 300거래일에서 잘린 건수

# ★ v2 개정 반영 (`00a-amendments-v2.md` M9-19)

- **경로 상한 300거래일 폐기.** 조사 세션 확인대로 현행 최장 보유가 301일(휠라홀딩스 081660,
  scan 2023-05-10)이라 300에서 잘려 1건이 불일치했다. 400도 부족하다(+40/−10·+50/−10이 342일).
  → **상한 없이 시계열 끝까지** 싣는다. 실측 경로 길이 중앙 303 · 최대 447.
- **합격 관문 문구:** "3,681건 전부 일치"는 상한을 없애면 실제로 통과 가능하다(조사 세션 결과
  result·days_held·gain_at_resolve_pct 각 3,681/3,681, 불일치 0). 문구는 그대로 두되,
  잘린 건이 생기면 **건수와 종목코드를 명시**한다.
- **★ 반올림 금지 (조사 세션이 찾은 것 — 지시서에 없던 사항):**
  가격을 소수 넷째 자리로 반올림하면 판정이 뒤집힌다. 실례 — +15/−10 · 티에프이(425420)
  2025-11-25가 원본 win·0일·+7.50% → 반올림분 loss·10일·−11.27%. 매수일 고가가 매수가의
  **정확히 1.15배**였고, 격자 문턱이 15·20·25·30·40·50% / 5·7·10·12%라 이런 정확한 비가 계속 나온다.
  → **o/h/l/c/ma20/entry_price는 반올림 없이 저장**하고, `*_pct`만 표시용으로 반올림한다.
  **12번 격자 판정에는 반드시 반올림 없는 o/h/l/c를 쓴다.**
- **메모리:** `_iter_pdata` 루프 **안에서** 필요 종목만 걸러 최대치를 낮춘다(실측 약 0.4GB, 15분).
- **추가 요청:** 경로 자료를 현행 규칙의 **진입 3,776키 전부**로 확장한다
  (확정 3,681 + ambiguous 74 + unresolved 21). 12번의 고정 유니버스 판(M2-i)과
  당일 손절 처리(M1)에 이 95건이 필요하다.
